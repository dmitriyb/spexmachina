# Change Proposal: One `plan` module — merge `impact` and `emit`

## Context

`spex impact` and `spex emit` are two pipeline stages with one consumer between them: the `ImpactReport` JSON that `impact` writes is read by `emit` and by nothing else — it is internal plumbing wearing the costume of a stable contract. The split predates the decouple migration, when an impact report still drove in-binary bead creation; post-decouple, and especially post-task-journal — where `Resolver` `f7775ac5f1f3` folds the journal on the emit side while `ActionClassifier` `76d72cbe00f3` consumes its pairings on the impact side — the two modules are one computation artificially halved: *(diff + tracker view + spec graph + git_head + proposal) → changeset*.

The cost of the split is concrete: a six-stage pipeline where five suffice (`validate → diff → impact → emit → adapter → ingest`), an intermediate schema maintained and version-checked for an audience of one, duplicated store/journal plumbing on both sides, and a CLI seam (`spex impact --json | spex emit`) whose flags (`--beads`, `--git-head`, `--proposal`) are split across two commands that only ever run together.

This proposal executes idea B — the last live remnant — of the retired draft `spec/proposals/obsolete/post-decouple-architectural-cleanup.md` (ideas A and C were settled and dropped by `2026-08-01-task-journal`). It assumes task-journal **and** `2026-08-11-event-keyed-linkage` have landed: the merged module folds the journal, and labels key on event ids. Unlike those corrections, **this change is deliberately structural**: component identity is `hash(module, type, name)`, so moving a component between modules changes its id even when its name survives. Every affected node is a removal plus an addition, and the proposal budgets for that honestly rather than pretending renames away.

## Proposed change

### The `plan` module replaces `impact` and `emit`

`spec/project.json`'s module list drops `impact` and `emit` and gains `plan` (path `plan/`), whose description states the merged contract: one deterministic pass from diff to changeset. The Go packages `impact/` and `emit/` merge into `plan/`; `cmd/spex/impact.go` and `cmd/spex/emit.go` are replaced by `cmd/spex/plan.go`.

**Components (8), all declared in `spec/plan/module.json` with new ids:** `BeadReader`, `NodeMatcher`, `ActionClassifier`, `Resolver`, `TopologicalSorter`, `IdempotencyLabeler`, `ChangesetBuilder`, and `PlanCommand`. Three current components have no successor: `ReportGenerator` `60d4747021ec` — the report it emits is machine JSON with a single consumer, and no human-readable rendering exists today to preserve (a `--explain` preview, if ever wanted, is new scope for a later proposal, not carried here) — and the two command components `ImpactCommand` `5d6813710879` / `EmitCommand` `cbe835d38c3e`, superseded by `PlanCommand`. `PlanCommand`'s flag surface is the union minus the seam: `--diff` (default stdin), `--beads`, `--git-head`, `--proposal`, `--out` (default stdout); `--json` dies with the report and the deprecated no-op `--bead-cli` is retired. There is no `--map`: task-journal retired the flag, and the journal's location is a function of `--spec-dir` alone.

**Module wiring:** `plan`'s `requires_module` is the union of the two modules' dependencies minus each other — merkle and map; `ingest`'s `requires_module` re-points from emit's module id to plan's new id. This wiring is load-bearing beyond documentation: the classifier derives every create op's `DepSpecNodeIDs` from the transitive `requires_module` closure, so it shapes the dependency graph of every bead in this epic.

**Apis:** `spex impact` `62b47fdb7f2d` and `spex emit` `7cccc4a96101` are removed; `spex plan` is added, `provided_by` `PlanCommand`. Hard cutover, no deprecated wrappers — single-user project, and the task-journal epic already retrains every consumer. The pipeline reads `validate → diff → plan → adapter → ingest` everywhere it is written down (README, CLAUDE.md, `spec/cli/` leaves, `spec/adapters/` and `spec/ingest/` mentions of "emit").

**Requirements:** the nineteen module requirements of `impact` and `emit` re-derive under `plan` from the same unchanged project requirements (`preq_id`s `9120788210c9`, `0a0f49f9be9b`, `6faeb216618a`, `81f8102ae1b5`, `58ea35f52b86`, `91f6f338de19`, `13c15bc3c865`) — eighteen of them one-to-one with re-worded descriptions, each keeping its own `preq_id`: the split forced no true duplicates, so nothing merges and no lineage re-parents. One has no successor: `cc987600950e` *Output impact report* (the artifact is gone); its parent `0a0f49f9be9b` remains covered by five surviving successors (`d165e2fe215e`, `06a081811e38`, `9199f27cb1e2`, `a3ecff50de68`, `116eb5f9906a`). No project requirement is edited.

**Author against the post-eid spec, not older files.** Task-journal re-describes six of these requirements and rewrites every surviving component leaf; `2026-08-11-event-keyed-linkage` re-describes three of those again (`5179e5a95653`, `0d468e176aaf`, `79c821e01654`) plus the labeler and reader leaves. Labels are `spex:<eid>`, `ref:spec_node` is gone from the vocabulary, the changeset is **v2**, and the adapter matches labels exactly in any status. Copying prose from pre-journal `spec/impact/` and `spec/emit/` files resurrects retired text; "byte-identical changesets" below means byte-identical to what the event-keyed pipeline emits.

**Data flows and tests:** `Impact analysis flow` `855e53793fdf` and `Emit flow` `dbe8d1e707d5` merge into one `Plan flow`; the five test sections re-home under `plan` with scenarios joined where they tested the seam itself (report-schema round-trips die with the schema).

### What the merge deletes outright

The `ImpactReport` JSON schema and its version checks; the report renderer; the `--diff`-file-in/`--out`-file-between plumbing of the seam; one of the two journal folds. The changeset format, the adapter contract, receipts, and ingest are untouched — `plan` emits byte-identical changesets modulo nothing at all: same ops, same order, same labels.

### Sweep obligations, stated in advance

Removing apis and components triggers the removal-time name sweep, and survivors are hard `surviving_name` errors that exit `diff` with 2 — this is the epic's largest collateral surface, budgeted below. The component names that re-home under `plan` are tolerated by the sweep's `suppressed_by_live_name` mechanic; the two api names `spex impact` and `spex emit` survive nowhere. The sweep scans `.md` **and `.json`** under `spec/` (only `spec/proposals/` and dot-prefixed files are skipped), and the full in-gate hit list is **fifteen files, forty tokenized mentions**: **`spec/merkle/`** (`arch_tree_builder.md`, `arch_hasher.md`, `arch_snapshot_store.md`, `arch_impact_classifier.md`, `arch_completeness_checker.md`, `arch_diff_command.md`, `flow_hash_computation.md`, `test_merkle_commands.md` — two mentions line-wrap mid-name and still count, the sweep tokenizes across newlines), **`spec/map/flow_bead_mapping.md`** (thirteen mentions — one line carries two), **`spec/proposal/`** (`arch_registrar.md`, `flow_proposal_lifecycle.md` — the proposal *module* is inside the gate; only `spec/proposals/` is skipped), **`spec/cli/flow_command_dispatch.md`**, and **`spec/ingest/`** (`arch_ingest_command.md`, `arch_snapshot_saver.md`, and `module.json` — the sweep reads json). `spec/adapters/` contributes **zero** sweep hits: its "emit" mentions are bare words and dead links into `spec/emit/` leaves — ordinary edit sites, like these silently-stale surfaces the sweep cannot flag: `spec/cli/arch_root_command.md` ("thirteen constructors" becomes twelve, "all sixteen" apis becomes fifteen), `spec/cli/test_root_command.md` (enumerates both bare command names), `spec/cli/arch_hash_id_command.md` + `test_hash_id_command.md` (worked examples keyed on the `impact` module), `spec/map/arch_map_command.md` (a worked example pointing at four `spec/impact/` paths), `spec/merkle/arch_diff_engine.md` (a pipeline arrow chain). Stage numbering needs no corpus-wide renumbering — every numbered-stage phrase lives inside the two deleted directories; what does change corpus-wide are the pipeline arrow chains (README, CLAUDE.md, and the merkle/ingest/map/proposal leaves above). `ReportGenerator`, `ImpactCommand` and `EmitCommand` have no live successors and their names already appear nowhere else in the gate. Out-of-gate but in-scope for cleanup beads: code comments at `merkle/doc.go`, `ingest/doc.go`, `cmd/spex/diff.go`; `cmd/spex/ingest.go` in both comment and code — it **imports the emit package** for `Changeset`/`ChangesetVersion`, which re-home into `plan`; `docs/architecture.md` and `docs/commands.md`; `skills/spec/SKILL.md` (the verbatim `impact:` refusal quote and the module-name example).

## Impact expectation

**This is a structural epic — the inverse of task-journal's shape.** Removed bead-producing nodes: 10 components + 2 data flows + 3 of the 5 test sections (the two single-`describes` command-test sections are coupled to their components and never had their own beads) — **15 obsolete actions**, each with a cleanup bead where code context would otherwise be lost; the moved-not-deleted nature of the code makes most cleanup beads trivially closable. Added: ~8 components, 1 data flow, and the multi-`describes` test sections under `plan` — **~11 creates plus the proposal-epic create**. The sweep's collateral: the fifteen swept files plus the six silently-stale leaves above are modified bead-producing surfaces — **another 15–21 modify pairs**. All told, **sixty to eighty operations**, with `/spec`'s enumeration authoritative.

**Module meta:** two module nodes removed, one added — changes refresh cannot absorb (meta is deliberately outside the absorbable set), so this epic runs through the full gate end to end, as intended.

**The journal records the dissolution** — the first structural epic it witnesses: every removed impact/emit node gets a `removed` event closing its lineage, every `plan` node an `added` event, and the cleanup tasks minted here carry their removal events' eids as labels (`spex:<eid>`, per `2026-08-11-event-keyed-linkage`), resolving against the journal from day one. What was the hardest part of the contracts migration to reconstruct afterwards becomes a queryable record.

**Out of scope:** any change to the changeset schema, adapter contract, or ingest (byte-identical output is the acceptance bar); the merkle hashing work (unchanged from task-journal's out-of-scope list); and any CLI compatibility shims. Prerequisites: `2026-08-01-task-journal` fully landed (it is — epic closed), and `2026-08-11-event-keyed-linkage` fully landed, its epic closed, consumers repinned — this proposal must not start while either's beads are open.
